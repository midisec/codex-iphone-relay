# 蓝牙链路诊断

2026-09-28，macOS 15.3.1 / iOS 26.6.1。纯蓝牙转发；USB 仅用于开发安装及日志抓取，USB 网络共享禁用。

## 已确认的等待

| 层级 | 观测 |
| --- | --- |
| 物理参数 | 系统重连日志：TX/RX 均为 2M PHY，TX/RX 数据长度均为 251 字节，连接间隔 30 ms，外设延迟 0 |
| L2CAP 接收能力 | Mac 声明 MTU/MPS 1251；iPhone 声明 MTU/MPS 2048 |
| L2CAP 信用额度 | 两端初始均为 65535；本次数据量未耗尽，没有补充信用消息 |
| 系统背压 | `bluetoothd` 反复记录栈已满、暂停读取，通道内部缓冲上限 1251 字节 |
| 控制器队列 | 手机侧观察到最多 16 个未完成 HCI ACL 包；约 97% 的入队时刻达到该值。完成通知成簇返回，邻近簇起点的中位间隔为 30 ms，常见每簇 4–5 个通知 |
| 应用发送窗口 | 4 块窗口测试中，有正文未提交时发送队列未断粮；上传约 86%–91% 的时间在等系统可写 |
| CPU 与调度 | 每轮上传写入调用累计约 2–3 ms；100 ms 主线程定时器的最大间隔约 103 ms |
| 双向控制消息 | 原 FIFO 队列中，Mac 的确认包等待最长约 5.49 s，心跳约 3.58 s |

手机 HCI 抓包中，Mac 大包常见分片长度为 `251×5 + 2`；反向常见一组 `251×4 + 247`，后跟一个 10 字节短包。大包重组时长中位数约 30 ms。缩小应用写入大小不能直接改变系统协商的 MTU/MPS。

上述信息来自系统日志和主机侧 HCI，不是空口嗅探；不能据此计算空口重传率，也不能宣称已到硬件极限。

## 对照试验

每轮上传和回传各 256 KiB 随机数据，三轮，SHA-256 全部一致。不同批次环境和重启状态不同，不把跨批次波动计为软件提速。

| 试验 | 上传 KiB/s | 下载 KiB/s | 处理 |
| --- | --- | --- | --- |
| 4 块窗口，16 KiB 写入 | 18.1–22.6 | 13.0–20.4 | 基线 |
| 1 块窗口，16 KiB 写入 | 20.4–23.5 | 18.2–20.5 | 等待转移到确认包，未证明稳定增益 |
| 手机重启后，4 块窗口 | 24.4–25.2 | 22.5–24.3 | HCI 抓取基线 |
| 1245 字节写入，每次让出 1 ms | 23.5–25.2 | 20.8–22.6 | 多数仍合并成原分片，已撤回 |

默认保留 4 块窗口、16 KiB 写入上限及事件驱动发送。

## v1.5.1 调度

确认包、心跳和配置保存确认可越过尚未写入的正文帧。已开始写入的帧完整发送后才切换；正文、请求头及结束消息保持原有顺序。此改动减少双向流控等待，不改变物理速率。

Mac 先行更新后的两轮双向交错测试全部通过，确认包最大排队从 5.49 s 降至 0.60 s。原队列第二轮出现过一次蓝牙断开，随后自动重连；不能仅凭本次对照认定该断开已修复。

两端 v1.5.1 更新后，移除手机诊断配置并重启，两轮双向交错测试全部通过，Mac 确认包最大排队为 0.74 s。每轮两条请求，各上传并回传 256 KiB，耗时 40.15 s / 39.82 s；总吞吐未证明提高。这里的排队时间指进入应用发送队列到写入本机 Stream，不是远端收到确认包的往返延迟。

关闭抓取后的三轮随机数据有效吞吐为 23.7 / 24.1 / 25.8 KiB/s，SHA-256 全部一致。三轮真实 Codex 追问均收到 `turn.completed`，保留上下文；测试进程仅允许访问 localhost。58 项核心检查、9 项 USB、34 项 API 编辑、36 项配置同步、8 项 Python 检查及 TCP 集成测试通过，iOS Release 构建、签名和安装通过。

## 复现应用时序

退出 Mac 转发 App 后运行：

```bash
mkdir -p .local
"/Applications/Bluetooth Codex.app/Contents/MacOS/BluetoothCodex" \
  --transport bluetooth --link-trace "$PWD/.local/ble.jsonl"
```

连接后在另一终端运行：

```bash
python3 scripts/benchmark_bluetooth.py --kind random --rounds 3 --size-kib 256
python3 scripts/analyze_link_trace.py .local/ble.jsonl --output .local/summary.json
```

- 每次使用新的抓取文件名；文件权限为 `0600`，最多记录 100000 个事件。
- 时序日志只包含消息类型、字节数和耗时，不包含正文、密钥或地址。
- `--bluetooth-upload-window 1` 可做窗口对照；允许范围为 1–4，默认 4。
- `--bluetooth-write-size 4096` 可做写入上限对照；默认 16384。
- 请求分阶段分析适用于单个请求依次运行的回传测试；并发测试只比较控制消息排队数据。
- 常规启动不带 `--link-trace`，不持续写入诊断文件。

原始 HCI 抓包可能包含凭证及正文，只在本机 `.local/` 保存，不随仓库分发。Apple 蓝牙日志配置在抓取后移除，按官方说明重启手机关闭日志。

[Apple 低延迟请求说明](https://developer.apple.com/documentation/corebluetooth/cbperipheralmanager/setdesiredconnectionlatency(_:for:))：低延迟是期望值，系统不保证采纳。
